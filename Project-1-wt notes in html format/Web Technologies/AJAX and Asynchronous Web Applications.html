AJAX and Asynchronous Web Applications

AJAX stands for Asynchronous JavaScript and XML. The name comes from an earlier period of web development, when XML was a common response format. Today, AJAX describes the broader technique of sending an HTTP request from JavaScript and updating part of the page with the response, without loading a new document. JSON is common, but a response can also be text, HTML, XML, or another resource type.

This pattern is useful when only one part of a page needs new information: searching a catalog, refreshing messages, checking a username, or submitting a form. It can reduce unnecessary page reloads and data transfer. The browser still needs a server or API to provide real data; AJAX is the communication pattern, not a server or database by itself.

Request and Response Cycle

1. A user action or another event starts a request to a server URL, often called an endpoint.
2. The browser sends the request, usually with a method such as GET to retrieve data or POST to send data.
3. The server returns a response containing a status and, when appropriate, a body such as JSON or text.
4. JavaScript checks the response, reads the body, and updates the needed DOM elements.
5. The rest of the document stays in place; the interface can show loading, success, or error feedback along the way.

What Asynchronous Means

A synchronous operation makes the next step wait for the current one to finish. A network request can take a noticeable amount of time, so browser APIs such as fetch() work asynchronously: they return a Promise representing work that will finish later. While the browser handles the network activity, JavaScript can continue responding to events and the page can remain interactive. When the response arrives, the promise is fulfilled with a Response , or rejected for a network-level problem. The response body is read separately and asynchronously. An async function lets us write this sequence with await ; await pauses that function until its promise settles, not the whole browser interface. Asynchronous does not mean that every JavaScript instruction runs in parallel.

Using Fetch and Handling Errors

fetch() is the modern browser API for HTTP requests. A successful call gives JavaScript a response object, but an HTTP error status such as 404 or 500 does not normally reject the fetch promise. Check response.ok before reading the body. Then use response.json() for JSON; it returns a promise too, and it can fail if the body is not valid JSON.
