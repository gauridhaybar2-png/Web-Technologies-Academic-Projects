Forms and Validation

Form validation checks user input before an application accepts or sends it. HTML provides basic constraints such as required , type="email" , and minlength ; JavaScript can add application-specific checks and feedback. The purpose is not simply to block mistakes; it is to guide the user, reduce errors, and save server resources by stopping bad data before it is submitted.

Typical validation includes checking that a field is not empty, that a password is long enough, that the email format matches expected syntax, and that required values are selected. In browser-side validation, JavaScript can show custom error messages and highlight the wrong input, while HTML attributes provide quick built-in rules. The browser also supports validation APIs such as checkValidity() , validity , and setCustomValidity() , which let developers combine built-in rules with custom business logic. However, because a user can disable JavaScript or send data directly to a server, final checks must still happen on the server side as part of secure application design.

HTML Validation Rules

Start with HTML attributes whenever possible. They describe the expected input directly in the markup, work with browser and assistive-technology features, and reduce the amount of JavaScript needed. The browser checks these constraints when a form is submitted unless validation is disabled with the novalidate attribute.

Validation Flow

1. Collect the values when the user submits the form. 2. Check basic constraints, such as required fields and valid input types. 3. Apply any extra rules specific to the application, then explain how to correct errors. 4. Only continue with submission when the values pass; validate them again on the server.

For custom checks, checkValidity() returns true when all constraints pass. reportValidity() asks the browser to display its validation feedback. The validity property gives details such as whether a value is missing or has the wrong format, and setCustomValidity(message) can add a custom error. Clear a custom error by calling setCustomValidity("") when the value becomes valid.
